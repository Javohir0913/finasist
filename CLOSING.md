# Закрытие месяца — что уже готово и что осталось дописать

Документ для того, кто будет делать модуль «Закрытие месяца». Вся обвязка,
на которую он опирается, уже в коде и работает; ниже — что именно готово,
что осталось, и какие грабли были убраны заранее.

---

## 1. Что уже работает

### Блокировка закрытого месяца

`app/periods.py` — единственное место, где живёт правило «закрытый месяц
не трогаем». Проверка уже подключена ко ВСЕМ эндпоинтам, которые пишут
первичку:

| Что | Где | По какой дате |
|---|---|---|
| Операции банка и кассы | `routers/transactions.py` | `doc_date` |
| Приход/расход ТМЦ, выпуск, продажа | `routers/inventory.py` | `doc_date` |
| Услуги | `routers/services.py` | `doc_date` |
| Зарплата | `routers/payroll.py` | `period` («ГГГГ-ММ») |
| Курс доллара | `routers/misc.py` | `rate_date` |
| Налоги | `routers/misc.py` | `accrued_date` |
| Займы и движения по ним | `routers/misc.py` | `opening_date` / `doc_date` |
| Входящее сальдо контрагента | `routers/organizations.py` | `opening_date` |
| Входящий остаток счёта и кассы | `routers/directories.py` | `opening_date` |
| Загрузка из Excel | `routers/imports.py` | построчно, ошибка видна в dry-run |
| Входящие остатки склада | `routers/materials.py`, `products.py`, `inventory.py` | даты нет — см. ниже |

Три функции:

* `assert_open(db, *dates, what=...)` — запретить, если хоть одна дата в
  закрытом месяце. При правке и удалении передаётся и СТАРАЯ дата: иначе
  документ можно было бы просто «вынести» из закрытого месяца, поменяв дату.
* `assert_period_open(db, "2026-01", what=...)` — то же, но период строкой
  (зарплата ведётся так).
* `assert_no_closed(db, what=...)` — для правок БЕЗ даты, которые задевают
  всю историю сразу (входящий остаток склада стоит в самом начале учёта).
  Запрещает, пока есть хоть один закрытый месяц.

Пока таблица `period_closes` пуста, ни одна проверка ничего не запрещает —
система ведёт себя ровно как раньше.

### Модель

```python
PeriodClose(period="2026-01", closed_at, closed_by, closed_by_name, note, snapshot)
PeriodSetting(period, key, value)   # помесячные ОС / износ / капитал
```

Таблицы создаются автоматически при старте (`Base.metadata.create_all`),
миграции руками не нужны.

### Права

`closing:view` / `closing:create` (закрыть) / `closing:delete` (открыть) —
уже в `permissions.py`, экран «Роли» подхватывает их сам.

### Готовые эндпоинты

* `GET /api/periods` — список закрытых месяцев со слепком.
* `GET /api/periods/checks?year=&month=` — готовность месяца к закрытию:
  `can_close` + список проверок + `snapshot`.

Проверки (`error` — закрывать нельзя, `warn` — можно, но стоит посмотреть):

| Код | Уровень | Что означает |
|---|---|---|
| `not_closed` | error | месяц ещё не закрыт |
| `prev_closed` | warn | предыдущий месяц закрыт (иначе входящие остатки поедут) |
| `rate_month_end` | error | введён курс на последний день месяца — по нему вся переоценка |
| `no_negative_stock` | error | нет позиций в минусе (минус = себестоимость списания неверна) |
| `balance_matches` | error | актив = пассив |
| `profit_matches` | warn | чистая прибыль ОФР = прирост нераспределённой прибыли |
| `payroll_done` | warn | зарплата за месяц рассчитана |
| `cashflow_codes` | warn | у всех операций месяца есть код ДДС |

## 2. Что осталось дописать

### Бэкенд — два эндпоинта

```python
@router.post("/{period}")          # право closing:create
async def close_period(period, note, current, db):
    period = valid_period(period)
    y, m = (int(x) for x in period.split("-"))
    checks = await period_checks(year=y, month=m, _=current, db=db)
    if not checks["can_close"]:
        raise HTTPException(400, detail="Месяц не готов к закрытию")
    db.add(PeriodClose(period=period, closed_by=current.id,
                       closed_by_name=current.full_name, note=note,
                       snapshot=await period_snapshot(db, y, m)))
    await db.commit()
    await record(db, current, "create", "period_close", period)

@router.delete("/{period}")        # право closing:delete
async def reopen_period(period, current, db):
    row = await db.get(PeriodClose, valid_period(period))
    ...
    # открывать можно только последний закрытый: иначе в середине истории
    # окажется дыра, и пересчёт закрытых месяцев станет неверным
    await db.delete(row)
    await record(db, current, "delete", "period_close", period)
```

`period_snapshot` и `period_checks` уже написаны в `routers/periods.py`.

### Фронтенд — экран «Закрытие месяца»

* список месяцев со статусом (закрыт / открыт / готов к закрытию);
* карточка проверок из `/api/periods/checks` — зелёные/жёлтые/красные;
* кнопка «Закрыть месяц» (активна при `can_close`), кнопка «Открыть» —
  только для последнего закрытого;
* сверка `snapshot` с текущим пересчётом: расхождение означает, что в
  закрытый месяц всё-таки что-то просочилось (страховка от дыр в блокировке).

Пункт меню добавляется в `frontend/src/lib/nav.tsx` с `perm: "closing:view"`.

## 3. Что было починено заранее (иначе закрытие ломалось бы)

**Склад не имел истории.** `Material.stock_qty` / `avg_cost` хранят только
«сейчас», и баланс подставлял сегодняшний склад в любую дату: закрыли январь —
после февральского прихода январский баланс менялся. Теперь `app/stock.py`
делает тот же реплей движений, что и пересчёт остатков, но с отсечкой по дате;
формула средней цены общая (`apply_receipt`), поэтому оценка на сегодня
копейка в копейку совпадает с экраном «Остатки по подразделениям».

**Займы и деньги брались «как сейчас».** `ledger.cash_position(on)` и
`ledger.loan_balances_at(on)` считают остаток на дату из первички; займ,
погашенный в марте, больше не исчезает из январского баланса.

**ОС, износ и капитал — одно значение на всю историю.** Износ обновляют
каждый месяц, поэтому прошлый баланс «уезжал» после каждой правки. Теперь
значение можно задать на месяц (`PeriodSetting`, эндпоинты
`GET/PUT /api/settings/periods/...`), а `periods.setting_value(key, on)`
берёт значение месяца → ближайшее более раннее → текущее из `Setting`.

**Нераспределённая прибыль — балансирующая величина.** Она сходится всегда
по построению, поэтому ошибку баланс показать не мог. Проверка
`profit_matches` сравнивает её прирост с чистой прибылью ОФР — расхождение
означает, что какая-то операция не попала в отчёт.

## 4. Что осознанно НЕ закрыто

**Правка карточки сотрудника** (`routers/payroll.py`, employees) не
блокируется закрытым месяцем. Сам расчёт зарплаты хранит уже посчитанные
суммы, но `division` и `expense_code` сотрудника участвуют в разнесении
затрат за прошлые месяцы. Блокировать перевод сотрудника из-за того, что
январь закрыт, — слишком грубо; если нужна строгость, добавьте
`assert_no_closed` в `update_employee` для этих двух полей.

**Переименование подразделений и кодов** (`routers/directories.py`) тоже не
блокируется: это справочники, а группировка отчётов идёт по строковому
названию. Массовое переименование задним числом изменит разрезы закрытых
месяцев.
